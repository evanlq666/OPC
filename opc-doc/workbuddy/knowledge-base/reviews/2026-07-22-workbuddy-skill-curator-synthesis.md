# 一句话结论

WorkBuddy 这轮 `AI Skill 策展人 IP` 不是要替代 `Evan下班了` 的小红书冷启动方向，而是更适合成为后端商业实验和高阶内容支线。前台仍应从普通职场人的 AI 焦虑与落地案例切入，但不建议再把 `周报 / 会议纪要 / 方案 / 项目复盘` 作为账号切入点；这些场景已经被大量 AI 教程和工具推荐覆盖，更适合作为后续实测素材。

# 证据或来源

## WorkBuddy 会话产物

- GitHub 目录：`2026-07-22-skill-curator-session/`
- 已完成阶段：资源盘点、利基定位、价值主张、商业模式。
- 核心方向：`Skill 策展人`，为 AI Agent 深度用户筛选值得安装和使用的 AI Skill。
- 核心价值：免费周刊（入口）+ 付费合集（壁垒）+ 公开评测标准（信任底色）。
- 高风险假设：
  - 用户是否愿意为 Skill 评测付费。
  - 免费周刊是否能转化为付费合集。
  - 一人 + Agent 是否能持续产出高质量内容。

## 已有 OPC 小红书方向

- 账号昵称：`Evan下班了`。
- 冷启动入口：普通职场人的 AI 焦虑 / FOMO。
- 内容主线：`AI 焦虑 -> AI 最小实践 -> 职场提效 -> 副业探索 -> 个人系统 / 一人公司`。
- 首发角度：大厂 AI 重组/裁员新闻带来的焦虑，不靠收藏教程缓解，而是从一个真实工作任务开始跑通。

# 聚合判断

## 1. 两条线的用户层级不同

`Evan下班了` 面向的是：

- 普通职场人。
- AI 小白和轻度使用者。
- 被 AI 新闻、裁员、工具更新刺激出焦虑的人。
- 还不知道该先把什么工作交给 AI 的人。

`Skill 策展人` 面向的是：

- WorkBuddy / Cursor / Copilot 等 AI Agent 深度用户。
- 已经知道 Skill 是什么，并且有安装、筛选、比较需求的人。
- 更接近高阶效率玩家、产品/开发/设计交叉用户。

这两类人可以连起来，但不能在冷启动主页和首篇内容里混讲。

## 2. Skill 策展可以做“后台能力”，暂时不要做“前台人设”

不建议小红书现在直接改成：

> 我是 AI Skill 策展人。

原因：

- 小红书普通用户不一定知道 Skill 是什么。
- 教育成本高，开篇容易变成概念解释。
- 会削弱 `Evan下班了` 的真人感和职场共鸣。

更适合的前台表达：

> 我会下班后实测一些 AI 工具 / Skill / 工作流，只留下普通人真能用上的。

这样既保留策展判断力，又不把用户挡在术语外面。

## 3. Skill 策展方向真正有价值的是“方法论”，不是高分结论

WorkBuddy 报告里 `29/30`、`12万+ Skill`、`12-18个月窗口`、`¥29.9-59.9 付费评测` 都需要验证，不应当直接当结论。

当前最可复用的是这套结构：

```text
发现大量工具/Skill
-> 初筛
-> 实测
-> 场景匹配
-> 同类对比
-> 坑点提示
-> 是否值得普通人使用
```

这套结构可以迁移到小红书内容：

- 不是“推荐一个工具”。
- 而是“我用一个真实工作场景测过，它适合/不适合谁”。

## 4. 最好的整合方式：双层 IP

### 前台 IP

```text
Evan下班了
```

用户感知：

- 一个有 8 年产品/项目经验的普通互联网人。
- 因为 AI 变化和职场焦虑，开始下班后做 AI 落地实验。
- 先帮普通人把周报、方案、复盘、个人系统这些事跑通。

### 后台能力

```text
AI Skill / 工具 / 工作流策展
```

用于支撑：

- 每周实测。
- 内容可信度。
- 后续虚拟资料。
- 更高阶用户的付费合集。

# 推荐调整

## 小红书冷启动不要改，但切入点要上移

继续沿用：

- 昵称：`Evan下班了`
- 简介：`8年产品/项目经验 / 下班后用AI解决真实工作问题 / 周报｜方案｜复盘｜个人系统`
- 首发：`看到大厂都在提 AI，我开始不敢只收藏教程了`

但内容表达要避免变成：

> 教你用 AI 写周报 / 做会议纪要 / 写方案。

更好的切入是：

> AI 工具和落地案例已经太多，普通人真正缺的是判断：哪些案例值得学、能迁移到自己的工作、能留下可展示的小成果。

## 内容栏目增加一个轻量支线

新增栏目名建议：

```text
下班实测
```

或：

```text
下班后的AI落地实验
```

栏目口径：

> 不做工具大全，只测一个真实场景：这个 AI 工具/Skill 能不能帮普通人解决一个工作问题。

## 2 周验证计划

### 第 1 周

发布 2 篇普通人入口内容：

1. 看到大厂都在提 AI，我开始不敢只收藏教程了
2. 普通人不是缺 AI 教程，是缺一个判断标准

目标：

- 测共鸣和评论场景。
- 看用户是否会说出自己被哪些 AI 案例、工具、教程搞焦虑。

### 第 2 周

发布 1 篇“下班实测”内容：

```text
我用同一个真实任务，测了 3 个 AI 工具
```

或：

```text
别问哪个 AI 工具最强，先看它能不能经得起这 3 个问题
```

目标：

- 测用户对“实测筛选”是否有收藏需求。
- 看评论是否出现“求模板 / 求工具 / 求流程”。

# 虚拟资料候选

如果普通人入口内容表现好：

- `普通人的 AI 落地案例清单`
- `职场 AI 最小实践模板包`

如果实测策展内容表现好：

- `AI 工具/Skill 评测表`
- `下班实测周刊`
- `普通人 AI 工具避坑清单`

# 风险和边界

- 不要过早承诺付费合集。
- 不要直接用 `Skill 策展人` 替换账号定位。
- 不要用未经验证的市场数字包装确定性。
- 不要把小红书写给深度 Agent 用户，至少冷启动前三篇不要这样做。
- 真正要验证的是：用户是否愿意收藏、评论、追问和跟做，而不是战略报告评分有多高。

# 下一步动作

1. 先按普通人入口发布首篇。
2. 第二篇不直接接周报，而是讲“普通人缺判断标准，不缺教程”。
3. 第三篇再引入轻量“实测筛选”口径。
4. 如果三篇里有 2 篇出现模板/工具/流程需求，再把 Skill 策展作为资料/周刊实验推进。

# 2026-07-22 修正

用户指出：`周报、方案、会议纪要、项目复盘` 这类任务现在已有大量 AI 内容，不一定适合作为账号切入点。

修正判断：

- 这些场景可以作为“例子”和“实测样本”，但不适合作为账号第一钩子。
- 第一钩子应从 `AI落地案例太多，普通人缺判断标准` 切入。
- Evan 的差异化不应是“我也教你写周报”，而应是“我帮你判断哪些 AI 案例真值得学，哪些只是看起来很热闹”。

OpenCLI 小红书搜索侧证据：

- `AI 周报` 已有写周报 Skill、周报自动生成器、AI 写周报去 AI 味等内容，部分点赞过百或过千。
- `AI 会议纪要` 已有高效会议纪要、录音转文字 App、AI 会议助手拆解、Prompt 直接抄等内容，部分点赞过千甚至过万。
- `AI 写方案` 已有 AI 写 PRD、Codex 写方案、提示词思路、AI 给方案后人做什么等内容。

新的内容母题：

```text
不是教你再学一个 AI 场景，
而是帮你判断哪个 AI 场景值得学。
```
