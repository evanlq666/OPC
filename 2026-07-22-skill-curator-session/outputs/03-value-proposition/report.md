## 一、目标客户细分确认

### 主要客群：AI Agent 深度实操型

| 维度 | 描述 |
|------|------|
| **身份标签** | AI Agent 工具（WorkBuddy / Cursor / Copilot 等）的深度使用者 |
| **使用深度** | 已安装并使用 Agent 工具，知道 Skill 能提效，有主动安装和尝试新 Skill 的行为 |
| **痛点视角** | 想用 Skill 但面对 12万+ Skill 供给不知从何选起，需要一个可信赖的筛选者 |
| **决策角色** | 个人效率主导的自主决策者——自己决定装什么 Skill、用什么工具 |
| **典型画像** | 产品经理、独立开发者、设计师、技术创业者——跨领域、追求效率、自驱型 |

### 为什么不是其他客群

| 被排除的客群 | 排除原因 |
|-------------|----------|
| AI 小白 / 刚接触者 | 需要先教育"什么是 Skill"，教育成本太高；他们是第二波用户而非第一波 |
| 企业采购决策者 | 决策链条长，不适合一人公司启动期覆盖 |
| Skill 开发者 | 受众太窄（候选2），适合作为第二阶段延伸 |
| 只看不用的信息消费者 | 不会付费，只适合免费层运维 |

## 三、Pains（痛点）

### 严重痛点

| ID | Pain | 严重度 | 现状 |
|----|------|--------|------|
| P1 | **信息过载导致决策瘫痪**：12万+ Skill，每天都有新增，试一个需要安装→配置→测试，试错成本极高 | 🔴🔴🔴🔴🔴 | 绝大多数人装了不到 10 个就放弃探索 |
| P2 | **平台评分不可信**：SkillHub 和觅游的评分体系不成熟，高分可能是因为描述写得好，不是因为真的好用 | 🔴🔴🔴🔴 | 用户用"碰运气"策略，随机下载高分 Skill |
| P3 | **场景匹配困难**：同一个"设计稿生成代码"类 Skill，有几十个——哪个适合 Figma 转 React？哪个适合截图转 HTML？用户无从判断 | 🔴🔴🔴🔴 | 逐个试，大部分试完就删 |
| P4 | **Skill 有隐性缺陷**：安装后才发现不支持某些功能、与当前工具版本不兼容、生成的代码质量不如预期 | 🔴🔴🔴 | 用户成为"自愿付费测试员" |
| P5 | **没有持续的跟踪信息**：装了一个好用的 Skill，但不知道开发者什么时候更新、什么时候弃坑 | 🔴🔴🔴 | 偶尔手动检查 |

### 中度痛点

| ID | Pain | 严重度 |
|----|------|--------|
| P6 | 同类 Skill 太多不知道怎么对比 | 🟡🟡🟡 |
| P7 | Skill 描述看不懂——技术术语太多，不知道实际能干什么 | 🟡🟡🟡 |
| P8 | 中文 Skill 和英文 Skill 混在一起，质量参差不齐 | 🟡🟡 |

### 现有替代方案及缺陷

| 现有方案 | 缺陷 |
|---------|------|
| **平台排行榜** | 只按下载量/评分排序，没有深度评测，容易被刷榜，高分≠好用 |
| **AI 工具博主推荐** | 多为"一句话推荐"，无实测、无对比、无场景说明；多为赞助内容 |
| **社区帖子（即刻/X/小红书）** | 碎片化，不成体系，质量极不稳定，难以作为决策依据 |
| **自己试** | 时间成本太高，且缺乏多维度判断能力（技术+产品+设计） |
| **开发者自荐** | 利益冲突，自卖自夸 |

## 五、Products & Services（产品与服务）

### 产品矩阵

| 层级 | 产品 | 形态 | 定价 | 节奏 |
|------|------|------|------|------|
| **A 入口层** | 「Skill 策展人」免费周刊 | 每周邮件/公众号推送，精选 3-5 个 Skill 简评 | 免费 | 持续运营 |
| **B 壁垒层** | 付费精选合集 | 单个 Skill 深度评测（安装→实测→对比→坑点→适用场景），每份 3000-5000 字 | 29.9-59.9 元/Skill | 周刊运营 3-6 月后上线 |
| **C 信任层** | 品牌信任资产 | 公开评测标准、评测方法论、Skill 质量维度框架 | 免费 | 与周刊同步建设 |
| **未来层** | 自有 Skill 产品 | 基于策展积累的需求洞察，开发自己的高质量 Skill | 29.9-99.9 元 | 策展 IP 成熟后 |

### 各层核心交付

#### A 入口层：免费周刊

- **内容**：每周 3-5 个 Skill 的快速评测（200-300 字/个）
- **结构**：Skill 名称 + 一句话介绍 + 适用场景 + 核心优势 + 1 个注意点
- **目标**：降低首次接触门槛，建立"这个策展人靠谱"的第一印象
- **分发**：微信公众号 + 即刻 + 小红书 + 邮件 Newsletter

#### B 壁垒层：付费精选合集

- **内容**：单个 Skill 的完整深度评测（3000-5000 字）
- **结构**：
  1. Skill 概述（做什么、怎么做、谁做的）
  2. 实测过程（安装→运行→结果→截图）
  3. 场景适配（什么场景下好用、什么场景不行）
  4. 同类对比（与 2-3 个同类 Skill 的对比）
  5. 坑点与注意（版本兼容性、已知问题、使用技巧）
  6. 综合评分（多维度打分 + 推荐指数）
- **目标**：让用户做决策时只需要这一份评测就够了
- **定价逻辑**：29.9-59.9 元/Skill——用户买的是"决策时间节省 + 踩坑风险规避"

#### C 信任层：品牌信任资产

- **内容**：
  - 公开评测维度与权重（技术质量 / 产品价值 / 用户体验 / 设计水准）
  - 评测流程透明化（怎么测的、测了什么）
  - Skill 分类体系（不是按技术栈，而是按用户场景分）
- **目标**：让用户不只看推荐结果，还理解推荐逻辑——建立方法论层面的信任

## 八、价值主张版本（三选一 + 组合）

### 方案 A：提效型——「省时间的人」

| 维度 | 内容 |
|------|------|
| **一句话** | 每周 5 分钟，帮你从 12万+ AI Skill 里挑出真正值得装的 |
| **核心逻辑** | 用户的痛点是"没有时间筛选"→ 策展人替你筛选 → 你只需要看结果 |
| **能量来源** | 免费周刊的媒体杠杆——广撒网建立认知 |
| **适用场景** | 冷启动期，需要快速积累第一批读者和信任 |
| **优点** | 门槛低、传播性好、无需用户付费就能体验价值 |
| **代价** | 提效型定位的付费转化逻辑较弱——"我免费看周刊就够了，为什么要付费" |
| **角色** | **A 入口**——这是让用户第一次认识"Skill 策展人"的门 |

### 方案 B：结果型——「拿结果的人」

| 维度 | 内容 |
|------|------|
| **一句话** | 不是推荐 Skill，是给你一个"装了这个 Skill 就能解决的那个问题"的确定答案 |
| **核心逻辑** | 用户想要的不是"好 Skill"，而是"我的问题被解决"→ 付费合集 = 确定性交付 |
| **能量来源** | 深度实测的判断力——不可替代的壁垒 |
| **适用场景** | 有一定信任基础后，用深度内容做付费转化 |
| **优点** | 付费意愿强、客单价高、用户粘性强、建立壁垒 |
| **代价** | 生产门槛高(每个 Skill 评测 3000-5000 字+实测)、冷启动期不适合直接推 |
| **角色** | **B 壁垒**——这是"Skill 策展人"不可替代的核心 |

### 方案 C：降风险型——「可信赖的人」

| 维度 | 内容 |
|------|------|
| **一句话** | 在 AI Skill 这个谁都可以说"好用"的领域，做那个你真的可以信的人 |
| **核心逻辑** | Skill 生态最大的问题是缺少信任→ 策展人通过方法论透明建立信任→ 信任 = 商业价值 |
| **能量来源** | 公开评测标准 + 持续一致性 + 独立判断 |
| **适用场景** | 贯穿始终——从第一天开始就铺设信任基础设施 |
| **优点** | 长期复利、难以复制、一旦建立就是护城河 |
| **代价** | 建立慢（信任需要时间）、无法短期变现、需要持续一致性输出 |
| **角色** | **C 底色**——这不是一个独立方案，而是所有方案都必须有的一层 |

## 九、组合版价值主张（✅ 创始人确认版）

### 分层策略

```
        ┌──────────────────────────────────┐
        │         C 底色：降风险型          │
        │     「可信赖的人」— 持续建立信任    │
        │   ┌──────────────────────────┐   │
        │   │    B 壁垒：结果型          │   │
        │   │ 「拿结果的人」— 付费合集    │   │
        │   │  ┌──────────────────┐   │   │
        │   │  │ A 入口：提效型     │   │   │
        │   │  │「省时间的人」      │   │   │
        │   │  │   免费周刊        │   │   │
        │   │  └──────────────────┘   │   │
        │   └──────────────────────────┘   │
        └──────────────────────────────────┘
```

### 组合版定位陈述

> **「Skill 策展人」** 为 AI Agent 深度用户提供三层价值：
>
> - **入口层**：每周免费周刊，5 分钟了解本周最值得关注的 AI Skill（提效）
> - **壁垒层**：深度实测付费合集，每个 Skill 一份 3000-5000 字完整评测，包含实测过程、场景适配、同类对比、坑点注意（结果）
> - **底色层**：公开透明的评测标准和方法论，让信任来自可复现的流程而非权威（降风险）
>
> **你是谁**：一个拥有 AI + 产品 + 前端 + 设计四维交叉视角的独立策展人，在 12万+ Skill 的供给海洋中，做那个帮你筛选的人。

### 分层对应的用户旅程

```
用户首次接触 → 免费周刊（A入口）
     ↓
持续阅读 4-8 周 → 建立信任（C底色）
     ↓
遇到具体选型需求 → 付费合集（B壁垒）
     ↓
持续订阅 + 口碑传播 → 品牌复利（C底色）
```

## 十、Agent 驱动策略

### 创始人关键约束

> 创始人希望后续由 AI Agents（如 WorkBuddy）来辅助搭建整个平台和体系——包括 Skill 策展工作流、内容生产 pipeline、付费系统和社区。

### Agent 驱动的策展工作流

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 发现    │ →  │ 初筛    │ →  │ 实测    │ →  │ 评测    │ →  │ 发布    │
│ Agent   │    │ Agent   │    │ 人工    │    │ Agent   │    │ Agent   │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
  自动监控         AI 打分         人工实测       AI 生成草稿     自动排版
  新品上架         筛选 top10      安装+运行      人工终审       多渠道发布
  抓取元数据                                       定调
```

| 环节 | Agent 负责 | 创始人负责 | 自动化率 |
|------|-----------|-----------|----------|
| 发现 | 监控 SkillHub/觅游新品、抓取元数据 | 设定监控范围 | 90% |
| 初筛 | AI 根据评分+描述+下载量打分排序 | 确认筛选标准 | 80% |
| 实测 | 辅助安装、运行、截图 | **实机操作 + 主观判断**（不可替代） | 40% |
| 评测 | AI 根据实测记录生成评测草稿 | **终审润色 + 定调**（不可替代） | 60% |
| 发布 | 自动排版、多渠道分发 | 确认发布 | 90% |

**人工不可替代的两个节点**：
1. **实测**：Skill 是否好用、有什么坑、和同类比好在哪——这些判断需要人的体验和跨领域视角
2. **终审**：内容的调性、判断的准确度、推荐的可信度——这些决定了策展 IP 的核心价值

### Agent 驱动的平台搭建

| 平台模块 | Agent 辅助方式 | 时间线 |
|---------|--------------|--------|
| 内容生产 pipeline | WorkBuddy Skill 策展工作流：发现→初筛→草稿→发布 | 第 1-3 月搭建 |
| 免费周刊 | AI 排版 + 多渠道分发 | 第 1 月起 |
| 付费系统 | Agent 辅助搭建支付+交付+CRM | 第 3-6 月 |
| 社区运营 | Agent 辅助内容分发、互动回复草稿 | 第 6+ 月 |
| 自有 Skill 开发 | Agent 辅助 Skill 架构设计+开发+测试 | 第 6-12 月 |

### 一人公司的 Agent 杠杆

> 整个「Skill 策展人」体系的设计原则：**创始人只做只有创始人能做的事（实测判断 + 终审定调），其他环节尽可能由 Agent 承担。**

这意味着：
- 不是"一个人做所有事"，而是"一个人 + 一组 Agent 做所有事"
- Agent 不是辅助工具，是这个 business 的第二生产力
- 策展工作流本身就是 Agent 编排的最佳实践——未来可以作为内容输出
