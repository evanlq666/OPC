# 「下班跑路指数」小工具 · 开发规格（以当前 HTML 产物为准）

> 版本：v3（2026-08-18）
> 对应产物：`xhs-minitool/下班跑路指数/`
> 对齐原则：本规格以当前已输出的 `index.html`、`js/questions.js`、`js/results.js`、`js/score.js`、`js/app.js` 为准；旧版 8 题 / S-A-B-C 四档规格已废弃。

---

## 一、产品概述

- **名称**：下班跑路指数
- **简介**：12 道下班情景题，测测你是下班跑路选手，还是工位黏住人。
- **形态**：小红书 Builder Hub 小工具，离线 H5 静态包，`index.html` 为唯一入口。
- **玩法**：12 道情景选择题，每题 A/B/C/D 四选一，点选即进入下一题。
- **结果**：总分 12-48，判定 8 档等级 + 2 个隐藏款；每档包含类型代码、搞笑称号和表情包文案。
- **传播逻辑**：结果卡用 Canvas 2D 渲染，页面内展示；用户点击按钮后通过 JSBridge 保存到系统相册，再分享给同事对答案。
- **隐私边界**：纯本地计算，只用 localStorage 保存最近一次结果，不采集、不上传用户数据。

## 二、文件结构

```text
xhs-minitool/下班跑路指数/
├── index.html
├── css/
│   └── style.css
└── js/
    ├── config.js
    ├── questions.js
    ├── results.js
    ├── storage.js
    ├── score.js
    ├── canvas.js
    └── app.js
```

脚本加载顺序必须保持：

```text
config.js -> questions.js -> results.js -> storage.js -> score.js -> canvas.js -> app.js
```

原因：所有模块通过 `window.*` 共享经典脚本作用域，无打包器、无 ES Module。

## 三、页面与交互流程

### 1. 封面页

对应 `#view-cover`。

必须包含：

- 标题「下班跑路指数」；
- Slogan；
- 「立即测试」按钮需在首屏可见；
- 10 个类型代码 + 称号预览；
- 开场引导；
- 隐私声明；
- 若 localStorage 有最近一次结果，展示「最近一次：X」和「查看结果」入口。

布局要求：

- 首页、答题页、结果页默认压缩在一屏内，不依赖滑动完成主流程；
- 窄屏 360×780 预览下，核心按钮和结果操作必须完整可见。

### 2. 答题页

对应 `#view-quiz`。

必须包含：

- 进度文案「第 X / 12 题」；
- 进度条；
- 当前题题干；
- 4 个大卡片选项；
- 「上一题」回改入口，第 1 题隐藏。

交互规则：

- 点选任一选项后先展示明确选中动画，再进入下一题；
- 第 12 题点选后直接结算；
- 选项不展示分值或等级暗示。

### 3. 结果页

对应 `#view-result`。

必须包含：

- 标题「你的跑路指数出炉了」；
- Canvas 结果卡；
- 上次结果与本次对比；
- 「保存到相册」按钮；
- 「我不服」按钮：重新测试；
- 「回到首页」按钮：返回首页并可查看最近一次结果；
- 隐私声明。

注意：结果页不展示「长按保存」或「复制文案」提示；保存失败、权限未授权或本地预览环境不支持时，只在页面内展示状态提示，不弹截图教学。

## 四、题目与计分

题目数据唯一来源：`js/questions.js`。

- 共 12 题；
- 每题 4 个选项；
- 每个选项包含 `key`、`text`、`score`；
- 分值范围为 1-4；
- 总分范围为 12-48。

题目清单：

1. 下班时间一到，你的第一反应是？
2. 晚上8点，领导在群里@你"在吗"？
3. 周六早上，工作消息弹出来，你？
4. 快下班，同事凑过来说"这个帮我看看"？
5. 看到隔壁工位到点还在敲键盘，你？
6. 领导 5:58 说"开个短会"，你？
7. 到点后，你收拾桌面的动作是？
8. 说到"准时下班"，你心里真实的想法是？
9. 周五下午四点，离下班还有两小时，你脑子里在想？
10. 项目 deadline 就在明天，你手头还压着一堆没做完，你会？
11. 领导临时丢来一个「不急，但今天最好给」的活，你手头正忙，你会？
12. 晚上十点，你刚洗漱完躺下，工作群弹出「明天早会的材料谁补一下」，你会？

## 五、等级判定

判定逻辑唯一来源：`js/score.js` + `js/results.js`。

判定顺序：

1. 先判隐藏款；
2. 再判普通 8 档。

| 总分 | 结果 |
|---:|---|
| 48 | 隐藏款：下班跑路的神 |
| 45-47 | Lv8 下班拿捏者 |
| 42-44 | Lv7 体面收工侠 |
| 39-41 | Lv6 准点候场选手 |
| 35-38 | Lv5 摇摆下班人 |
| 30-34 | Lv4 工位端水大师 |
| 26-29 | Lv3 想走不敢走 |
| 22-25 | Lv2 隐形加班预备役 |
| 13-21 | Lv1 隐形加班奴 |
| 12 | 隐藏款：哦不人·天花板 |

档位序号：

```text
哦不人·天花板 = 0
Lv1 = 1
Lv2 = 2
Lv3 = 3
Lv4 = 4
Lv5 = 5
Lv6 = 6
Lv7 = 7
Lv8 = 8
下班跑路的神 = 9
```

再测对比：

```text
本次档位序号 - 上次档位序号
```

结果大于 0 显示进步，等于 0 显示持平，小于 0 显示退步，文案保持轻松、不责备。

## 六、本地存储

模块：`js/storage.js`。

localStorage key：

```text
xblp_last_result
```

存储结构：

```json
{ "order": 3, "total": 28, "ts": 1787068286089 }
```

约束：

- 只保存上次结果、总分和时间戳；
- 不保存每题答案；
- 不上传任何数据；
- 存储不可用时静默降级，不影响答题主流程。

## 七、Canvas 结果卡

模块：`js/canvas.js`。

能力要求：

- 使用 Canvas 2D；
- 按屏幕宽度自适应；
- 乘以 `devicePixelRatio` 高清绘制；
- 绘制类型代码、搞笑称号、表情包舞台、梗句、人设文案和中性底部说明；
- Canvas 仅用于页面展示和生成 `data:image/png`，不做文件下载。

当前尺寸逻辑：

- 逻辑宽度：屏幕宽度减边距，限制在 280-380；
- 高宽比：3:4；
- DPR 上限：3。

## 八、小工具容器规范

本项目按离线 H5 小工具实现，需满足：

- `index.html` 位于 zip 根目录；
- 所有资源使用相对路径；
- 无外部网络资源；
- 无内联 `<script>`；
- 无行内事件；
- 无 `type="module"`；
- 无 `eval()` / `new Function()` / WebAssembly；
- 无 `fetch` / XMLHttpRequest / WebSocket / EventSource；
- 无 `navigator.clipboard` / `document.execCommand('copy')`；
- 无 `a[download]` / blob 下载；
- 无 iframe / object；
- 不跳站外链接。

相册保存只允许使用官方 `window.xhs.miniTool.writeTempFile` 与 `window.xhs.miniTool.saveImageToPhotosAlbum`；不读取用户相册内容，不调用剪贴板、下载或外链能力。
